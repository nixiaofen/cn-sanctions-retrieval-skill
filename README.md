# 中国管制/制裁清单检索路径（无接口场景）

> 一个 WorkBuddy Skill —— 教你如何核查**中国官方那些"没有查询接口"的制裁与出口管制清单**。

**一句话**：OFAC、欧盟那些清单能直接下 CSV 拉下来比对，但中国的清单不给 API、不给数据下载。本 skill 把"只能人工检索"这条路沉淀成标准 SOP。

---

## ⚠️ 能力边界（使用前必读）

**能做的**：把"查中国这几张无接口名单"的人工动作标准化，并产出可追溯的核查记录。

**不能做的** —— 请勿过度承诺：

| # | 限制 | 说明 |
|---|---|---|
| 1 | **不能批量自动化筛查** | 官方无结构化数据、无 API，无法像 OFAC 那样一次导入上千主体自动比对。**适用中小体量交易对手与重点高风险主体**；**数万主体的大规模筛查不适用**，成本不可承受 |
| 2 | **不保证清单范围完整** | 本 skill **只覆盖下表 4 张"以主体名称列名"的清单**，不等于中国全部限制（见下方"不在范围内"） |
| 3 | **不做主体同一性认定** | 名称检索天然存在同名风险。产出的是"**名称匹配候选**"，命中与否须经**人工身份交叉核验** |
| 4 | **结论有时效** | 清单不定期更新，且**网页可能存在缓存与更新延迟**；重大交易应结合官方咨询渠道确认 |
| 5 | **不是法律意见** | 仅为"是否出现在官方名单"的事实核查，不构成合规结论或法律意见 |

### 不在本 skill 范围内的限制类型
| 类型 | 归口 |
|---|---|
| **物项类管制**（两用物项和技术管制清单——按物项归类/ECCN 类比，不做名称比对） | 商务部／海关总署 |
| **外商投资安全审查** | 外商投资主管部门 |
| **行业专项限制名单**（国防科工、生态环境、药监等各自的管理名单） | 各行业主管部门 |
| **不当域外管辖相关措施**（禁执令、阻断措施等） | 《反外国不当域外管辖条例》体系 |
| **境外清单**（美/欧/联合国/英/日等有接口的） | 走 `cn-sanctions-screening` |

## 什么时候需要它

✅ 需要
- 供应商准入 / 交易对手筛查，要核查对方是否被中国官方列入限制名单
- 收到"中国清单没有 API 怎么查"这类问题
- 有历史核查结论，需要**复核**是否仍然成立

❌ 不需要
- 美、欧、联合国、英、日等**有可机读下载接口**的清单 —— 直接拉 csv/xml 做自动比对更快更准
- **数万主体的大规模批量筛查** —— 本 skill 只做人工标准化，不做批量自动化

> 配套：`cn-sanctions-sources`（官方源索引）／`cn-sanctions-screening`（境外有接口清单的自动筛查）。本 skill 只补"中国无接口清单"这一段。
>
> ⚠️ **二者互补，不是替代。** 境外清单走自动筛查，中国无接口清单走本 skill 的人工检索 SOP；**两者不可互相取代，也不得因完成其一而省略另一**——跨境交易须两段都做。

## 覆盖范围：中国 4 张可按名称筛查的清单

### 经济制裁类（3 张）

| 清单 | 管理机关 | 依据 | 措施 |
|---|---|---|---|
| **不可靠实体清单** | 商务部工作机制 | 《不可靠实体清单规定》＋对外贸易法＋国家安全法 | 禁对华进出口、禁在华新增投资、禁高管入境、取消高管居留许可、**处两倍罚款** |
| **反制清单** | 外交部 | 《反外国制裁法》 | 冻结境内财产、禁境内主体交易合作；对个人还含不予签发签证、不准入境 |
| **恶意实体清单** | 国务院 | 《反外国不当域外管辖条例》（2026-04-07 生效） | 反制和限制措施；**首批名单状态须每次核查时确认** |

### 出口管制类（1 张）

| 清单 | 管理机关 | 依据 | 措施 |
|---|---|---|---|
| **出口管制管控名单** | 商务部 | 《出口管制法》＋《两用物项出口管制条例》 | 禁止向其出口两用物项、在跑出口停止、特殊情况报商务部申请 |

> ⚠️ **最容易搞错的一点**：在"出口管制管控名单"里，"两用物项"指的是**被限制的内容**，而清单列的**仍然是实体**，所以可以按名称筛查。别因为名字里有"两用物项"就把它归到物项清单里。

## 标准流程（五步）

1. **定位权威来源** —— 搜索引擎只作引线，**结论必须回官网正文核实**
2. **定位公告/名单正文** —— 按时间倒序，区分"法规"与"名单公告"
3. **进入正文提取名单** —— 注意分页、折叠、JS 渲染
4. **名称比对** —— 法人颗粒度 ＋ 双语 ＋ 归一化 ＋ **身份交叉核验**
5. **截图留痕** —— 列表页 ＋ 正文页各一张

另附**执行检查清单**（10 项打勾防漏步）与**复核流程**（结论有时效，建议月度复核）。

### 核查顺序（固定，四张一张不落）
**① 不可靠实体清单 → ② 出口管制管控名单 → ③ 反制清单 → ④ 恶意实体清单**

效力最强的排在最前；第 ①② 张同属商务部，一次检索即可覆盖。

### 风险分级（决定深度与留痕，**不决定查哪几张**）
⚠️ **四张永远全查**，分级只调整检索深度、留痕等级与复核强度——避免因风险判断失误而漏查某张清单。

| 项 | 高风险 | 低风险 |
|---|---|---|
| **清单范围** | **4 张全查** | **4 张全查** |
| 留痕 | 全套留痕 ＋ 双截图 ＋ 二级复核 | 最小证据留痕（清单、文号、访问日期、结论） |
| 复核 | 月度 | 月度 |

**高风险判定**（满足任一）：涉两用物项/军民两用技术；涉台军售或涉台业务；新建立关系；位于高风险管辖区或曾被列任何名单；管理层关注、金额重大、有负面涉华报道。

**升级机制**：低风险主体一旦出现候选/近似项、新增敏感物项、外部信息负面变化 → 立即升为高风险重做。留痕须记**分级结论、依据、分级人**。

### 留痕要点
`references/record-keeping.md` 提供三套模板：
- **首次核查记录**（含逐清单结论表、同名主体甄别表）
- **阴性结果记录模板** —— "未命中"必须单独举证：四张逐一写明"已核查＋公告文号＋名单发布日＋结论"，只写两个字等于没查
- **截图要点清单** —— 截图须可见 URL、机关、文号、发布日期、主体所在段落、官网页脚

### 第 4 步必做：身份交叉核验
名称匹配**不等于**主体同一。凡出现命中或候选，须用下列辅助信息**至少核验两项一致**：

- 主体识别码：境内**统一社会信用代码**；境外注册号／公司号／LEI／税号
- 注册地／注册地址、成立日期
- 经营范围、行业、规模、官网与邮箱域名
- 母子公司与集团结构（区分母公司、子公司、分公司）

不一致 ⇒ 判"非同一主体"，按未命中处理并记录排除理由；信息不足以排除同名 ⇒ 保持"候选"。

## 三个最容易踩的坑

**1. 法人颗粒度（最高频误判）**
清单对象是**法人**，不是集团。同一集团的不同法人可能落在不同清单，母公司往往未被列。
> 实例：`波音防务、空间与安全集团`（不可靠实体清单＋出口管制管控名单）与 `波音密苏里州圣路易斯市分公司`（反制清单）是**两个不同法人**，而 **The Boeing Company 母公司未列入任何清单**。

**2. 名称是「中文名（英文名）」双语**
中英文名**各比对一次**。只有英文名时直接做英文子串比对，**不必先音译**。比对前须归一化（大小写、标点、公司后缀），否则 `AERKOMM INC.` 与 `Aerkomm Inc.` 会漏。

**3. 未见名单 ≠ 未命中**
制度已生效但名单尚未发布时，记录"条例已生效、首批未发布"，**不判"未命中"**。

## 配套脚本

`scripts/match_names.py` —— 名称归一化 ＋ 精确命中 ＋ bigram 候选标记（纯标准库）

```bash
python scripts/match_names.py --names names.txt --list extracted.txt
python scripts/match_names.py --names names.txt --list extracted.txt --out report.md
```

⚠️ **脚本只做名称字符串匹配，不含任何主体身份信息，无法识别同名主体。输出只能作为候选线索**，主体同一性须人工核验。候选一律交人工终判，脚本不自动定性"命中"。

## 重要提醒

- **不是法律意见**，不构成合规结论；重大交易仍需法律专业判断。
- **结论仅对核验日有效**，务必按 `references/recheck.md` 定期复核（建议月度）。
- **网页可能存在缓存与更新延迟**；重大交易、必要项目应结合官方咨询渠道确认。
- **模糊命中必须人工终判**并二级复核，脚本只做辅助标记。
- **跨境交易还需核查其他管辖区**（走 `cn-sanctions-screening`）及其他不在范围内的限制类型。
- 本 skill 只索引/摘录官方源，**不建受制裁主体数据库**。
