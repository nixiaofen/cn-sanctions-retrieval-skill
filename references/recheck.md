# 复核（定期重跑）流程

核查结论**只对核验日有效**。清单会新增、调整、移除实体，因此必须设定复核节奏。本文件给出复核细则与记录模板。

## 一、何时触发复核

| 触发 | 说明 |
|---|---|
| **定期** | 建议**月度**（与 `cn-sanctions-sources` 的 GitHub Actions 月度检链节奏一致）。高风险交易对手可缩短至双周 |
| **相对方变更** | 名称、注册地、法人形式、并购导致主体变更 |
| **怀疑清单更新** | 行业新闻、境外媒体提示某管辖区调整清单 |
| **问询** | 监管问询、客户问询、内部审计要求 |
| **制度生效待发布** | 如恶意实体清单首批名单公布后，须立即对相关主体复核 |

## 二、复核怎么做（原则）

1. **重新完整走一遍五步流程**，不得凭上次结论延伸推断。清单变动可能与该主体无关，但流程能保证不漏。
2. **只查变动增量，但仍以官网为准**：可先看该机关最新公告有无涉及本主体；若无，再确认公告本身不是最新一期。
3. **四项必查**：
   - 是否有**新公告**（按时间倒序，确认当前公告仍是最新一期）
   - 原"**命中**"是否**仍在列**（可能被移出／调整）
   - 原"**未见名单**"的清单是否已**发布首批**（如恶意实体清单）
   - **措施**是否有变（如罚款倍数、限制范围调整）
4. **法人颗粒度复检**：主体是否发生法人变更（合并、注销、名称变更）导致原结论指向错误法人。

## 三、复核结论分类

| 复核结果 | 处理 |
|---|---|
| **维持** | 结论与首次一致 → 追加复核记录，更新核验日 |
| **变更**（命中↔未命中、或措施变化） | 追加复核记录，**标注变化原因与新文号**，并评估是否需通知相关业务方 |
| **新增命中** | 说明此前未被列入、本期新增，立即按命中处置 |
| **已移出** | 记录移出依据（公告文号），保留原记录不得删除 |
| **仍待发布** | 制度已生效但名单未发布 → 延续"待持续更新"表述，不改判"未命中" |

## 四、复核记录模板

**追加**在首次记录之后，不覆盖原记录。

| 字段 | 内容 |
|------|------|
| 复核日期 | YYYY-MM-DD（本次访问日） |
| 复核对象 | 同首次（法人全称） |
| 复核范围 | 4 张全查／指定单张 |
| 上次核验日 | YYYY-MM-DD |
| 结论变化 | 维持／变更（变更类型）／新增命中／已移出／仍待发布 |
| 变化原因 | 新公告文号 ＋ 变化内容（新增、移出、措施调整） |
| 当前措施 | 按最新公告原文列全 |
| 截图路径 | 本次复核截图（列表页＋正文页） |
| 复核人 | 姓名 |
| 是否需业务通知 | 是／否（如是，写明通知对象与日期） |

## 五、与留痕的关系
- 首次记录与历次复核记录**同档保存**，形成可追溯链条（满足合规审计调阅）。
- `cn-sanctions-sources` 仓库的月度 CI 负责**链接可用性**校验；本 skill 的复核负责**名单内容与主体归属**的确认，二者互补。
